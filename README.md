# 일당노트 (Ilddang Note)

> 외국인 근로자를 위한 다국어 근무기록·급여계산 모바일 웹앱

**"내가 일한 걸 아무도 부정할 수 없게 만든다."**
오늘 어디서 몇 시간 일했는지만 누르면, 이번 달 받을 돈이 나옵니다.

---

## 이 제품이 하는 일

계산은 미끼이고, 실제 제품은 **근로자 본인이 만든 일별 원장(原帳)** 입니다.
임금 체불·시급 축소·근무시간 누락 분쟁에서 근로자가 가진 유일한 반대 증거가 이 기록입니다.

| 사용자 상황 | 앱이 해결하는 것 |
|---|---|
| 공장이 자주 바뀜 (인력사무소 파견) | 근무지를 스티키 카드로 저장 → 다음부터 탭 한 번 |
| 근무시간이 불규칙 (4h / 8h / 12h) | 프리셋 버튼 + 자유 입력 병행 |
| 야근·특근 배율 계산이 어려움 | 8시간 초과분·휴일 자동 배율 적용 |
| 3.3% 떼고 실제 얼마 받는지 모름 | 세전 / 공제 / 실수령 3단 표시 |
| 한글을 못 읽음 | 다국어 + 아이콘·색상 중심 UI, 하루 기록 3탭 |
| **임금 체불 시 증거가 없음** | **미수금 추적 + 기록 내보내기 (핵심 가치)** |

## 기술 스택

```
┌────────────── Vercel ──────────────┐
│  Next.js 15 (App Router) + TS      │
│  output: 'export' (정적 빌드)       │
│  Tailwind CSS v4                   │
│  Dexie.js (IndexedDB) ← 로컬 우선  │
│  next-intl (클라이언트 전용 구성)   │
│  PWA (오프라인·홈화면 설치)         │
└────────────┬───────────────────────┘
             │ 동기화 시에만 호출 (Phase 2)
             ▼
┌────────────── Render ──────────────┐
│  Node 20 + Express + TypeScript    │
│  Prisma + PostgreSQL               │
│  JWT + bcrypt(PIN)                 │
└────────────────────────────────────┘
```

**왜 로컬 우선인가**
1. 공장 내부는 통신이 불안정합니다
2. Render 무료 플랜은 15분 무활동 시 슬립 → 첫 요청 최대 50초 지연
3. 로그인 없이 즉시 사용 가능해야 이탈이 없습니다

→ 모든 읽기/쓰기는 IndexedDB에서 즉시 처리하고, 서버는 백업·기기 이전용으로만 씁니다.
**Phase 1은 서버 없이 완전히 동작합니다.**

## 개발

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # 급여 엔진 테스트 (Vitest)
npm run lint     # tsc --noEmit
npm run build    # 정적 export → out/
npm run icons    # PWA 아이콘 재생성 (의존성 없이 PNG 직접 인코딩)
```

### 배포 (Vercel)

프레임워크 자동 감지로 별도 설정 없이 붙습니다.

| 항목 | 값 |
|---|---|
| Framework Preset | Next.js |
| Build Command | `npm run build` |
| Output Directory | (자동) |
| 환경변수 | 없음 — Phase 1은 서버를 쓰지 않습니다 |

`output: 'export'`로 정적 빌드되며, `vercel.json`에 보안 헤더와
`sw.js` 무캐시 정책이 들어 있습니다.
Phase 2에서 Render API를 붙일 때 `NEXT_PUBLIC_API_URL`을 추가합니다.

### 현재 구현 범위

| 영역 | 상태 |
|---|---|
| `src/lib/payroll` | ✅ 급여 엔진 + 22개 테스트. 연도별 요율 테이블, 4종 공제, 5인 미만, 자정 넘김, 야간 비례배분 |
| `src/lib/db` | ✅ Dexie 스키마 v1 (Phase 1-B에서 UI와 연결) |

## 개발 원칙 (반드시 지킬 것)

### 계산
- 시급·공제방식은 **기록 시점 스냅샷**을 쓴다. 근무지 설정을 바꿔도 과거 기록 금액은 절대 변하지 않는다
- 최저임금·보험 요율은 **연도별 테이블**에서 날짜 기준으로 조회한다. 하드코딩 금지
- 반올림은 **일급 단위 1회만**. 구간별 반올림 후 합산 금지
- 월 공제액 = `Σ(근무지별 세전 × 근무지별 요율)`. 전체 세전에 단일 요율을 곱하면 틀린다

### 데이터
- `createdAt`은 어떤 경로로도 갱신하지 않는다 (증거력의 핵심)
- 근무지는 **삭제 불가**, `isArchived`만 가능
- 모든 금액 필드는 원 단위 정수. 부동소수 금지
- Dexie 스키마 변경 시 `upgrade()` 필수 — 마이그레이션 실패 = 사용자 데이터 영구 소실

### UI
- 색·타이포·컴포넌트 규격은 **DESIGN-ILGIK.md가 우선**한다
- 주 CTA는 `primary #1c1c1e` black pill. 브랜드 노랑은 로고·태그 칩 전용
- 모든 버튼·칩·탭·배지는 `rounded.full`
- `font-weight: 700` 이상 사용 금지 (400 / 500 / 600만)
- 터치 타깃 최소 56px (주 CTA 64px) — 시스템 기본 44px를 제품 요구로 상향
- 모든 금액에 `font-variant-numeric: tabular-nums`

### 법적·윤리
- 모든 금액 표시 옆에 **"예상 금액이에요"** 고지
- Phase 1은 개인정보를 일절 수집하지 않는다
- 번역 검수를 통과하지 않은 언어는 릴리즈에 포함하지 않는다 (오역 = 임금 오해)
- 톤: "이건 불법이에요"가 아니라 "이만큼 못 받았어요"
