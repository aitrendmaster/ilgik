> 배포: Vercel(프론트) + Render(API·DB)

## PART 1. 기획

### 1.1 한 줄 정의

**"오늘 어디서 몇 시간 일했는지만 누르면, 이번 달 받을 돈이 나온다."**

### 1.2 문제 정의

| 사용자 상황 | 앱이 해결할 것 |
|---|---|
| 공장이 자주 바뀜 (인력사무소 파견, 단기) | 근무지를 카드로 저장 → 다음부터 탭 한 번 |
| 근무시간이 불규칙 (4h / 8h / 12h) | 프리셋 버튼 + 자유 입력 병행 |
| 야근·특근 배율 계산이 어려움 | 8시간 초과분·휴일 자동 배율 적용 |
| 3.3% 떼고 실제 얼마 받는지 모름 | 세전/공제/실수령 3단 표시 |
| 한글을 못 읽음 | 11개 언어 + 아이콘·색상 중심 UI |
| 임금 체불 시 증거가 없음 | 기록 내보내기(이미지·PDF·CSV) |

**가장 큰 가치는 계산이 아니라 "기록의 증거화"입니다.** 임금 체불 발생 시 근로자가 스스로 만든 일별 기록은 노동청 진정 시 실제 증빙 자료가 됩니다. 이 점을 제품의 핵심 포지셔닝으로 잡습니다.

### 1.4 저문해 사용자를 위한 UX 원칙 (가장 중요)

이 앱의 성패는 기능이 아니라 **"글자를 못 읽어도 쓸 수 있는가"**에 달려 있습니다.

1. **첫 화면 = 언어 선택.** 국기 아이콘 + 해당 언어 자국어 표기(예: `Tiếng Việt`, `ไทย`). 한글로 "언어 선택"이라 쓰지 않습니다.
2. **최소 탭 원칙.** 하루 기록은 **3탭 이내** 완료: 근무지 카드 탭 → 시간 프리셋 탭 → 저장.
3. **색으로 구분.** 각 근무지에 색상 + 이모지를 자동 배정. 글자를 못 읽어도 캘린더의 색 점으로 "어디서 일했는지" 인지 가능.
4. **숫자는 크게, 글자는 적게.** 최소 폰트 16px, 터치 타깃 최소 56px.
5. **금액은 항상 3단 표시.** 세전 → 공제 → 실수령. 실수령만 크게, 나머지는 작게.
6. **오프라인에서 동작.** 공장 안은 신호가 약합니다. 로컬 저장 우선, 네트워크는 동기화에만 사용.
7. **되돌리기 항상 가능.** 삭제는 즉시 실행하지 않고 5초 Undo 스낵바.
8. **로그인 장벽 없음.** 설치 즉시 사용 가능. 계정 연결은 "백업하기"라는 이름으로 나중에 유도.

### 1.6 급여 계산 로직 (핵심 명세)

#### 기본 상수
```
DEFAULT_HOURLY_WAGE = 10,320원   // 2026년 최저임금
OVERTIME_MULTIPLIER = 1.5        // 연장근로 가산
HOLIDAY_OVER8_MULTIPLIER = 2.0   // 휴일 8시간 초과
NIGHT_EXTRA = 0.5                // 야간(22:00~06:00) 추가 가산 (옵션)
WITHHOLDING_3_3 = 0.033          // 소득세 3% + 지방소득세 0.3%
```

#### 하루 계산 절차
```
1) 실근로시간 = (퇴근 - 출근) - 휴게시간
   ※ 휴게시간 기본값: 8시간 이상 근무 시 60분 자동 차감 (사용자 수정 가능)

2) 근무 유형 판정
   [평일]
     기본시간 = min(실근로, 8)        → 배율 1.0
     연장시간 = max(실근로 - 8, 0)     → 배율 1.5
   [휴일/특근 체크됨]
     휴일시간 = min(실근로, 8)         → 배율 1.5
     휴일초과 = max(실근로 - 8, 0)     → 배율 2.0

3) 야간 가산 (설정에서 ON일 때만)
     22:00~06:00 구간 근로시간 × 0.5 배율분 추가 합산

4) 일급(세전) = Σ(구간시간 × 시급 × 배율), 원 단위 반올림
```

#### 월 정산
```
월 세전합계 = Σ 일급
공제액 = 월 세전합계 × 공제율
실수령 예상 = 월 세전합계 - 공제액
```

#### ⚠️ 공제 방식은 반드시 사용자가 고를 수 있어야 합니다

3.3%만 고정하면 오답이 나오는 경우가 많습니다.

| 옵션 | 공제율 | 대상 |
|---|---|---|
| **3.3% 원천징수** (기본값) | 3.3% | 인력사무소·프리랜서 계약. 4대보험·주휴수당 없음 |
| **4대보험 근로자** | 약 9.4% (국민연금 4.5 + 건강보험 3.545 + 장기요양 + 고용보험 0.9) | 정식 근로계약. 주휴수당 발생 |
| **공제 없음** | 0% | 현금 일당 |

→ 근무지(회사)별로 공제 방식을 저장합니다. A공장은 3.3%, B공장은 4대보험인 경우가 흔합니다.

#### 참고로 표시할 안내 (계산 결과 하단)
- 이 금액은 **예상치**이며 실제 지급액과 다를 수 있습니다.
- 5인 미만 사업장은 법적으로 연장·휴일 가산수당(1.5배) 의무가 없습니다.
- 주 15시간 이상 근무한 근로자는 **주휴수당**을 받을 권리가 있습니다 (4대보험 옵션 선택 시 Phase 2에서 자동 계산).
- 임금을 못 받으면 **고용노동부 1350** (외국어 상담 지원)으로 신고할 수 있습니다.

### 1.9 비주얼 디렉션

AI가 만든 티가 나는 기본값(크림 배경 + 세리프 + 테라코타)을 피하고, **작업 현장의 사물**에서 가져옵니다.

| 토큰 | 값 | 근거 |
|---|---|---|
| `--ink` | `#16233A` | 작업복 인디고 데님 |
| `--safety` | `#F5C518` | 안전조끼 형광 노랑 — CTA 전용 |
| `--paper` | `#F7F8FA` | 배경 |
| `--card` | `#FFFFFF` | |
| `--money` | `#0E9F6E` | 실수령 금액 |
| `--alert` | `#E8590C` | 미확정·경고 |
| 근무지 색상 팔레트 | 8색 고채도 세트 | 색맹 대응 위해 이모지 병행 |

- **타이포**: Pretendard(한/영) + Noto Sans 스크립트별 서브셋. 금액은 `font-variant-numeric: tabular-nums`, 무게 700.

### 1.10 기술 스택 & 배포 아키텍처

```
┌────────────── Vercel ──────────────┐
│  Next.js 15 (App Router) + TS      │
│  Tailwind CSS v4                   │
│  Dexie.js (IndexedDB) ← 로컬 우선  │
│  next-intl (11개 로케일)           │
│  PWA (오프라인·홈화면 설치)        │
└────────────┬───────────────────────┘
             │ 동기화 시에만 호출
             ▼
┌────────────── Render ──────────────┐
│  Node 20 + Express + TypeScript    │
│  Prisma ORM                        │
│  PostgreSQL (Render Managed)       │
│  JWT + bcrypt(PIN)                 │
└────────────────────────────────────┘
```

**왜 로컬 우선인가**
1. 공장 내부는 통신이 불안정합니다.
2. Render 무료 플랜은 15분 무활동 시 슬립 → 첫 요청에 최대 50초 지연. 저문해 사용자에게 치명적.
3. 로그인 없이 즉시 사용 가능해야 이탈이 없습니다.

→ **모든 읽기/쓰기는 IndexedDB에서 즉시 처리**하고, 서버는 백업·기기 이전용 동기화에만 씁니다. Phase 1은 서버 없이도 완전히 동작해야 합니다.

**인증 설계**: 이메일·비밀번호는 이 사용자군에게 장벽입니다. **휴대폰 번호 + 6자리 PIN** 방식으로 하고, SMS 인증은 비용 문제로 Phase 3에서 검토합니다. Phase 2에서는 `deviceKey` 기반 익명 계정에 폰번호를 연결하는 방식으로 시작합니다.

### 🔧 Phase 1-A — 급여 계산 엔진 (테스트 우선)

```
/lib/payroll에 급여 계산 엔진을 순수 TypeScript 함수로 구현한다.
UI보다 먼저, 테스트와 함께 만든다. Vitest를 설치해서 쓴다.

## 상수 (/lib/payroll/constants.ts)
DEFAULT_HOURLY_WAGE = 10320
OVERTIME_MULTIPLIER = 1.5
HOLIDAY_BASE_MULTIPLIER = 1.5
HOLIDAY_OVER8_MULTIPLIER = 2.0
NIGHT_EXTRA_MULTIPLIER = 0.5
NIGHT_START_HOUR = 22
NIGHT_END_HOUR = 6
DEDUCTION_RATES = {
  RATE_3_3: 0.033,      // 소득세 3% + 지방소득세 0.3%
  INSURANCE_4: 0.0940,  // 국민연금 4.5 + 건강보험 3.545 + 장기요양 + 고용보험 0.9 (근사치)
  NONE: 0
}

## 핵심 함수

calculateDayPay(input): DayPayResult
input: {
  startTime?: string   // "HH:mm"
  endTime?: string     // "HH:mm", 자정 넘김 처리 필수
  totalMinutes?: number  // 시각 대신 총 시간만 입력한 경우
  breakMinutes: number
  isHoliday: boolean
  hourlyWage: number
  nightPayEnabled: boolean
}
result: {
  workedMinutes, regularMinutes, overtimeMinutes,
  nightMinutes, breakdown[], grossPay
}

계산 규칙:
1. 실근로시간 = (endTime - startTime) - breakMinutes
   endTime < startTime이면 익일로 간주해 24시간 더함
2. 평일: min(실근로,8h)는 배율 1.0 / 8h 초과분은 배율 1.5
3. 휴일(isHoliday=true): min(실근로,8h)는 배율 1.5 / 8h 초과분은 배율 2.0
4. nightPayEnabled=true이면 22:00~06:00 구간에 걸친 근로시간에 0.5배를 추가 가산
   (시각 입력이 없고 totalMinutes만 있으면 야간 가산 계산은 건너뛴다)
5. grossPay = Σ(구간분/60 × 시급 × 배율), 원 단위 반올림
6. breakdown 배열에 각 구간(라벨, 분, 배율, 금액)을 담아 UI에서 내역 표시 가능하게 한다

calculateMonthlyPay(logs, deductionType): MonthlyPayResult
  { grossPay, deductionAmount, deductionRate, netPay, totalMinutes, byWorkplace[] }

## 반드시 포함할 테스트 케이스
- 09:00~18:00, 휴게 60분 → 8시간, 82,560원
- 09:00~22:00, 휴게 60분 → 기본 8h + 연장 4h → 82,560 + 61,920 = 144,480원
- 20:00~05:00 (자정 넘김), 휴게 60분 → 8시간
- 휴일 10시간 근무 → 8h×1.5 + 2h×2.0
- 야간수당 ON, 22:00~06:00 근무
- 4시간 단시간 근무 (휴게 0분)
- 월 합계 3.3% 공제 vs 4대보험 9.4% 공제 비교
- totalMinutes만 입력한 경우

전부 통과할 때까지 진행한다.
```

## PART 4. 주의사항

**법적 고지 필수**
급여 계산은 참고용이며 법적 효력이 없습니다. 앱 내 모든 금액 표시 옆에 이를 명시하고, 최초 실행 시 사용자가 확인하도록 합니다.

**번역 검수는 타협하지 마세요**
기계번역만으로 출시하면 임금 관련 오해가 발생할 수 있습니다. 최소한 베트남어·태국어·네팔어는 원어민 검수를 받으시기 바랍니다. 외국인노동자지원센터나 관련 NGO에 협조를 요청하면 도움을 받을 수 있는 경로가 있습니다.

**개인정보**
휴대폰 번호를 수집하는 순간 개인정보처리방침이 필요합니다. Phase 1(로컬 전용)에서는 개인정보를 전혀 수집하지 않으므로 부담이 없습니다. Phase 2 진입 전에 방침 문서를 준비하세요.

**공제율 최신화**
4대보험 요율과 최저임금은 매년 바뀝니다. 상수를 코드에 하드코딩하되 연도별 테이블 구조로 만들어 두면 갱신이 쉽습니다.
