DESIGN-ILGIK 적용 결정

시스템 매핑 — 무엇을 바꿨나

기획서의 색 방향(작업복 인디고 #16233A + 안전조끼 노랑 CTA)과 DESIGN-ILGIK가 충돌합니다. Miro 시스템이 우선하므로 아래와 같이 재배치했습니다.

토큰 재배치

주 CTA
안전조끼 노랑 → black pill #1c1c1e + rounded.full. DESIGN-ILGIK는 노랑을 CTA에 쓰는 것을 금지합니다. 흰 배경 위 검정은 대비 21:1로 오히려 시인성이 더 좋습니다
브랜드 노랑
#ffd02f는 로고 마크·태그 칩에만. 앱 안에서는 공제율 배지 정도로 절제
실수령
--money #0E9F6E → success-accent #00b473
미지급·경고
--alert #E8590C → coral-light 지면 + coral-dark #600000 글자 (badge-tag-coral 규격)
선택 상태
ink 반전 유지 + 폼 선택은 brand-blue 2px 테두리 + featured 배경 (pricing-card-featured 규격)
굵기
800 → 400 / 500 / 600만. Miro는 700을 쓰지 않습니다. 위계는 크기와 색으로 만듭니다

은유 전환 — 급여봉투 → 스티키 노트 중요

기획서의 시그니처는 급여봉투 카드(톱니 절취선 + 종이 노이즈 + 도장 스탬프)였습니다. 이는 DESIGN-ILGIK의 flat + hairline 원칙, "무거운 그림자 금지", 파스텔 카드 규격과 정면으로 충돌합니다.

→ 근무지를 스티키 노트로 재정의했습니다. Miro의 파스텔 피처 카드는 원래 화이트보드 스티키 팔레트에서 온 것이고, "오늘 어디서 일했는지 붙여두는 메모"라는 제품 행위와 정확히 겹칩니다. 봉투는 월 1회 순간이지만 스티키는 매일의 기록 행위와 맞습니다.

정산 카드는 rounded.xxxl 파스텔 카드로 남기고, 절취선은 1px dashed 한 줄로만 흔적을 남깁니다. 노이즈 텍스처와 도장 스탬프는 제거하고, "예상" 고지는 badge-tag-coral pill로 대체했습니다.

근무지 스티키 팔레트 8종

DESIGN-ILGIK의 파스텔은 서로 너무 가까워(coral-light / brand-red / orange-light) 8개를 구분할 수 없습니다. 문서 Known Gaps의 "실제 화이트보드 스티키는 마케팅 지면보다 진하다"를 근거로 파스텔 5 + 진한 3으로 구성해 명도까지 갈랐습니다. 색맹 대응은 이모지 병행으로 보강합니다.

brand-yellow · coral-light · teal-light · brand-rose · orange-light — 글자 #1c1c1e
진한 3

지키지 않은 규칙 2개 (의도적)

터치 타깃
DESIGN-ILGIK는 pill 버튼을 40~44px로 정의합니다. 이 앱은 56px(주 CTA 64px)로 올립니다. 저문해·현장 장갑 사용자가 대상이라 제품 요구가 우선합니다. 형태(pill·radius·색)는 그대로 따릅니다
Roobert PRO
한글 글리프가 없고 CDN 로드도 막혀 있습니다. font-family에 1순위로 두되 실제 렌더는 Pretendard가 담당합니다. Roobert의 기하학적 성격과 가장 가까운 한글 face입니다

보험 체크박스가 필요한 이유 계산

국민연금은 상호주의라 캄보디아·네팔·미얀마·태국 등은 당연적용 대상이 아니고, E-9은 고용보험도 임의가입입니다. 9.4% 일괄 적용은 최대 사용자군에서 틀립니다.

국적 판정 로직을 앱에 넣으면 법령 해석 책임을 지게 되므로, 사용자가 급여명세서를 보고 체크만 하게 합니다. 체크할 때마다 badge-tag-yellow 요율 배지가 실시간 갱신됩니다.

기타 공제 (스크롤 아래)

  • 소개비 · 숙소비 · 식대 · 차비 + 직접 입력
  • 모드: PER_DAY / PER_MONTH / RATE
  • 인력사무소는 일당의 8~10%를 소개비로 뗍니다. 이게 빠지면 앱 금액과 실제 봉투가 안 맞고, 사용자는 앱이 틀렸다고 판단합니다

삭제 대신 보관

  • 삭제 버튼은 존재하지 않습니다. 과거 기록의 외래키가 깨지고 증거가 사라집니다
  • "이제 여기 안 나가요" = isArchived. 목록에서 숨고 과거 기록은 유지
  • 시급·공제방식을 수정해도 과거 기록 금액은 절대 바뀌지 않습니다 (hourlyWageSnapshot · deductionSnapshot)
